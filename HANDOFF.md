### Dashboard facts
- Routes (`src/libs/routes.js`): protected (`RequireAuth`): dashboard, documents, document detail, products, credit history, API credentials, analytics, profile, profile/edit, help, checkout, payment success/cancel (+ aliases). Public: `/` (RootEntry), login, register, forgot/reset password, verify-email, 404.
- `RootEntry` forwards `/?token=` to `/verify-email` and `/?session_id=` to the checkout success page, else to `/dashboard`. The backend's verification email and Stripe return URLs hit the **root**.
- API: `http://api.joinfield.ai/api/v1` (HTTP, not HTTPS). CRA `"proxy"` in package.json and `vercel.json` rewrites `/api` and `/uploads` to `http://api.joinfield.ai`. `vercel.json` also has a catch-all to `index.html` and `/demo` rewrites. API notes: the memory/artifact "Joinfield API field notes" (https://claude.ai/code/artifact/e0d0cbaa-e0e7-4e15-a45e-98efc990055a) has the verified endpoint shapes and traps.
- Theme: design "G — Mono" (black/white/grey, red only for danger). CSS custom properties in `src/styles/_tokens.scss` (`$jf-tokens` light/dark pairs), `variables.scss` maps `$Color-*` to `var(--jf-*)`. Axis 1 `data-theme` = light/dark/system (`libs/themeMode.jsx`, key `joinfield-theme`, pre-paint script in `public/index.html`). Axis 2 `data-layout` = classic/rail (key `joinfield-layout`). Rail = dark sidebar, icon-only collapse (`joinfield-sidebar`), cream canvas in light mode; styles in `_Rail.scss`. Classic is the default and the one the user prefers. Keep both.
- Libraries that may break on React 19 / newer majors: `react-input-mask`, `notistack` 2, `react-date-range`, MUI 5 → current major, `@mui/lab`. Check each before choosing versions.
- Code uses absolute imports from `src` (`baseUrl: src`) and `window`/`localStorage`/`document` in ~37 files, so most dashboard pages will be client components.
- Storage keys keep the `joinfield-` prefix on purpose (renaming would reset users' saved preferences).
- Design reference: Claude Design canvas "Joinfield Dashboard Theme" https://claude.ai/code/artifact/61fbbd1d-0cc1-4668-acf4-32563f978163 (page 1 = G — Mono). Static demo of it in the dashboard repo: `public/demo/`.

   Progress: auth pages (login, register, verify-email, forgot/reset password) and the signed-in shell (`app/(dashboard)/app/(protected)/layout.tsx` → `RequireAuth` → sidebar, header, search, usage and theme menus) plus the home page, Buy credits (`/app/products`), the landing hand-off (`/app/checkout?plan=`) and the Stripe return pages (`/app/checkout/success|cancel`), Documents (`/app/documents`, with the upload sheet), document detail (`/app/documents/[uuid]`), credit history (`/app/credits`), API keys (`/app/api-keys`), analytics (`/app/analytics`) the profile with its edit screen (`/app/profile`, `/app/profile/edit`), help (`/app/help`) and the dashboard 404 are ported and pixel-identical to the source: every page of the CRA app is in. Unknown `/app/...` addresses hit `app/(dashboard)/app/[...missing]`, which calls `notFound()` so the dashboard's own `not-found.tsx` renders; other unknown addresses get the landing's `global-not-found.tsx`. The dashboard 404 answers HTTP 200, not 404: the dashboard renders in the browser only, so the server has already sent the shell when the page throws (the CRA app on Vercel answered 200 too; the pages are `noindex`). Help writes `?q=` with `window.history.replaceState`, which Next keeps in sync with `useSearchParams`. `use-debounce` was replaced by `libs/useDebouncedCallback.js`; `DialogConfirm` now takes React content for `desc` instead of an HTML string; every caller passes JSX or plain text. MUI 7+ also stopped emitting compound classes (`MuiButton-containedPrimary`, `-containedRed`, `-outlinedWhite`, `MuiTabs-flexContainer`, `MuiLinearProgress-barColorSecondary`); the SCSS now pairs the variant and colour classes instead, wrapped in `:where()` to keep the old specificity. Re-run the class audit (every `Mui*-*` name in the SCSS against what MUI emits) after each MUI upgrade. The CRA app's extra Stripe return aliases were dropped: the app sends Stripe its own `success_url` / `cancel_url`. When porting, move MUI's removed `PaperProps` / `MenuListProps` / `InputProps`-style props to `slotProps` (left in `FormInput`); MUI 9 ignores them without an error.
5. **Wire the contract**: `shared` route constants and the landing → dashboard entry points. Done so far: Sign in → `ROUTES.login`, trial/sign-up → `ROUTES.register`, pricing Check out → `ROUTES.checkout`; `APP_URL` is gone. Signed-in visitors see one "Dashboard" button in the landing header instead of "Sign in" / "Request demo" (no redirect from `/`): the dashboard's `tokenStorage` writes `SIGNED_IN_HINT_KEY` (no token) next to its tokens, the landing layout's pre-paint script turns it into `<html data-signed-in>`, and CSS picks the buttons, so pages stay static and nothing flashes. The pricing page prices with the Field API now (same-origin `API_BASE` = `/api/v1` from the contract: `GET products`, `POST products/price`), not the Hirize one. It keeps one guest basket per visit (the price call creates it, later calls replace its lines) and hands it over as `/app/checkout?basket_id=`; checkout claims it with `POST products/assign-basket` (after login if needed) and opens Buy credits with it. A basket edited since its last price goes as `?plan=<fieldProductId>:<count>` instead, which checkout prices again. Checked end to end against the real API: guest → login page with the basket kept; signed in → Buy credits shows the same lines and total. The API sells no subscriptions, so the Subscription switch and "30% off" badge are hidden behind `SUBSCRIPTIONS = false` in `plan-content.tsx`; the 1,000-call minimum (a Hirize rule) is gone, the API prices from 1. Still on the Hirize host: the ai-agents email form and `/api/contact` (`API_URL_PROD`), hence `connect.hirize.hr` in the CSP; `DASHBOARD_API_URL(_DEV)` / `API_URL_DEV` are now unused. Product icons follow Buy credits: the API's `icon` path is not served, so its file name is matched against `public/assets/icons/products/` (only CV Parser and Invoice Parser exist, copies of the dashboard's) and the rest get the Field mark (`pricing/product-icon.tsx`). Backend wishes, not blockers: a price quote that does not create a basket (or tier prices in `GET products`), and a rate limit plus expiry for ownerless baskets.
